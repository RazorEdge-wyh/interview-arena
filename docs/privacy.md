# 隐私与数据流（Privacy）

## 1. 静态版（GitHub Pages）数据流

```
候选人浏览器
 ├── 题库 data/questions.json（静态文件）
 ├── 选择/自我介绍/问答 → 只存在内存 + localStorage（本机）
 ├── [可选] 浏览器直接调用 AI API（Key 存在 localStorage）
 │      请求内容：评分提示词 + 你的自我介绍/回答
 │      接收方：你配置的 AI 服务商（如 DeepSeek）
 ├── 加密：浏览器 WebCrypto（RSA-OAEP + AES-GCM + gzip）
 └── 发送：复制 / 下载 / 本机邮件客户端（mailto）
```

**不存在**：本项目没有后端、没有数据库、没有统计脚本、没有第三方埋点。
**唯一的外发**：你自己触发的 AI 调用，以及你主动发送的加密报告。

### 浏览器里存了什么

| key | 内容 | 何时清 |
|---|---|---|
| `ia_settings_v1` | API Base URL、模型名、API Key | 点「清除 Key」或清站点数据 |
| `ia_draft_v1` | 4 题选择、自我介绍草稿 | 点「重新开始」 |

## 2. Streamlit 版数据流

```
浏览器 → Streamlit 服务端（会话内存）→ AI API / SMTP
```

- 会话结束即释放，不写数据库。
- AI Key、SMTP 授权码放在 Streamlit Secrets（服务端），不会下发到浏览器。
- 若部署到 Streamlit Community Cloud，数据会经过其服务器；请自行评估合规要求。

## 3. 加密设计

| 层 | 算法 | 作用 |
|---|---|---|
| 内容压缩 | gzip | 减小体积，便于邮件正文传输 |
| 对称加密 | AES-256-GCM（随机 key + 12 字节 IV） | 加密报告内容，防篡改 |
| 密钥封装 | RSA-OAEP（SHA-256） | 用面试官公钥加密 AES key |

加密包结构：

```json
{ "v": 1, "alg": "RSA-OAEP-256+A256GCM+gzip",
  "to": "…", "createdAt": "…",
  "key": "<base64 RSA 密文>", "iv": "<base64>", "data": "<base64 密文>" }
```

- 公钥在仓库（`public_key.json`），只能加密。
- 私钥由面试官本地保管（建议 `_keys/`，权限 600，永不提交）。
- 拿到加密包但没有私钥，无法还原任何分数或回答。

### 3.1 明文邮件 vs 加密报告（2026-10-23 更新）静态版默认提供「跳转邮件客户端」：**邮件正文是明文的**，包含分数、自我介绍原文、追问与回答、AI 点评（这是面试官直接阅读所需）。
同时可勾选在正文末尾附带加密密文，用于校验内容未被篡改。

因此：

| 发送方式 | 正文内容 | 保密性 |
|---|---|---|
| 跳转邮件（默认） | 明文报告 + 可选密文 | 明文受邮件服务商/收件箱安全影响；密文部分仍保密 |
| 仅加密报告 | 只有密文 | 内容保密，但面试官需私钥解密后才能读 |

如需"邮件正文不出现原文"，请取消勾选或只用「仅加密报告」路径。无论哪种方式，页面都不会把内容上传到本项目的服务器（本项目没有服务器）。

### 3.2 浏览器解密页（decrypt.html）

- 页面在 `/decrypt.html`：粘贴加密 JSON、选择私钥 PEM，点「解密」。
- 解密全部用 WebCrypto 在本地完成：`RSA-OAEP` 解出 AES 密钥 → `AES-GCM` 解密 → `gzip` 解压 → 渲染报告。
- **私钥只存在于浏览器内存**：不写入 localStorage、不上传、不经过任何后端；刷新页面即清除。
- 建议在可信设备/离线环境使用；解出的明文可下载为 JSON 或直接打印成 PDF。
- 页面不做"真伪认证"：公钥公开，任何拿到公钥的人都能生成合法密文，需结合面试过程判断。

## 4. 威胁模型与边界

| 风险 | 是否覆盖 | 说明 |
|---|---|---|
| 中间人窃听邮件/微信 | ✅ | 内容是密文 |
| 候选人偷看报告 | ✅ | 只有公钥，不能解密 |
| 面试官设备丢失 | ⚠️ | 私钥泄露则可解密；建议私钥加密码/放密码管理器 |
| 伪造报告 | ❌ | 公钥公开，任何人都能生成合法密文；需结合面试过程与身份核验 |
| AI 服务商看到内容 | ⚠️ | 调用 AI 时内容会发给服务商；敏感信息请先脱敏或用本地评分 |
| 浏览器被恶意插件读取 | ⚠️ | localStorage 中的 Key/草稿可被同源脚本读取；用干净浏览器 |

## 5. 合规提醒

- 测评与 AI 评分**不得作为自动淘汰依据**；《个人信息保护法》要求处理敏感个人信息（含测评结果）取得单独同意，并告知处理目的与方式。
- 如需长期保存候选人报告，建议：加密存储、设置保存期限、限制访问权限、提供删除渠道。
- 不要把 API Key 写进前端代码或公开仓库；静态版的设计前提是**候选人自带 Key，或只在自己的设备上使用**。

## 6. 建议的使用方式

1. 面试官在自己的设备上打开页面，填 Key，完成测评；
2. 或把 Pages 链接发给候选人，让其**自带 Key** 完成，再把加密结果发回；
3. 面试官用私钥解密，把明文 JSON 存入受控目录（不要进聊天记录/公开仓库）。
