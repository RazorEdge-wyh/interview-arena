# 评分口径与自定义（Scoring）

> 目标：让分数**可解释、可复现、可调整**，而不是一个黑盒数字。

## 1. 三段式结构

```
综合分 = (能力性格测评 × 0.30 + 自我介绍 × 0.35 + AI 追问 × 0.35) / 可用权重之和
```

缺失模块时自动归一化，例如跳过自我介绍：`(测评×0.30 + 问答×0.35) / 0.65`。

区间解释：

| 综合分 | 含义 | 建议动作 |
|---|---|---|
| ≥ 80 | 强推荐进入下一轮 | 直接约复试，追问弱项 |
| 65–79 | 推荐进入下一轮 | 约复试，重点验证风险点 |
| 50–64 | 待定，建议补面 | 针对低分维度补 15 分钟专项面试 |
| < 50 | 暂不建议推进 | 记录原因，避免只看单一维度 |

> 分数只用于**相对比较**，不建议做跨岗位、跨批次的绝对阈值。

## 2. 能力性格测评（4 题，30%）

每题 4 个选项，每个选项对 4 个维度给 0–5 分：

| 维度 | 类型 | 含义 |
|---|---|---|
| 分析判断 analysis | 能力 | 拆解问题、定位原因、基于证据决策 |
| 执行推进 execution | 能力 | 把想法落地、推进节奏、交付结果 |
| 协作沟通 collaboration | 性格 | 同步信息、处理冲突、带动他人 |
| 抗压韧性 resilience | 性格 | 面对否定与失败时的恢复与成长 |

归一化方式：某维度得分 / 该维度在 4 题所有选项中的理论最大值 × 100。

> 注意：这是"倾向"而非"能力上限"。选项没有绝对正确答案，高分只代表更接近"成熟做法"。

## 3. 自我介绍（35%）

四个维度各 0–25，合计 0–100：

| 维度 | 看什么 | 高分特征 |
|---|---|---|
| 结构清晰 structure | 现状—行动—结果—反思 | 3 段以内讲清，有起承转合 |
| 具体可验证 specificity | 数字、时间、角色、结果 | 有 2 个以上可追问的量化事实 |
| 自我认知 selfAwareness | 优势、短板、改进动作 | 能说清"我哪里不行、怎么补" |
| 岗位匹配 roleFit | 经历与岗位要求对应 | 明确说"为什么是这个岗位" |

AI 提示词要求：分数克制、理由引用原文关键词、total 为四维之和。

无 API Key 时使用本地规则评分（长度、数字密度、结构词、反思词、岗位词），仅作粗筛，页面会标注"本地规则评分"。

## 4. AI 追问（35%）

先根据自我介绍生成 4 个追问（动机 / 难点与解法 / 结果归因 / 岗位匹配），候选人作答后再评分：

每答 0–25，维度：具体性、逻辑性、反思深度、岗位匹配；合计 0–100。

低分特征：只说结论没有细节、把团队结果据为己有、遇到追问就绕开、没有边界意识。

## 5. 如何自定义

所有内容在 `data/questions.json`：

```jsonc
{
  "weights": { "mcq": 0.30, "intro": 0.35, "qa": 0.35 },
  "dimensions": { "analysis": { "label": "分析判断", "type": "ability" }, ... },
  "questions": [
    { "id": "q1", "tag": "...", "title": "...",
      "options": [
        { "text": "...", "scores": { "analysis": 2, "execution": 5 } }
      ] }
  ],
  "introRubric": [ { "key": "structure", "label": "结构清晰", "desc": "..." } ],
  "qaRubric": [ ... ]
}
```

- 换题：改 `questions`，保持每题 4 个选项、`scores` 覆盖 4 个维度。
- 换权重：改 `weights`（三项之和建议为 1）。
- 换维度：改 `dimensions` 的 key/label，并同步选项里的 `scores` 键。
- 换评分标准：改 `introRubric` / `qaRubric` 的 `desc`，AI 提示词会自动带上。

## 6. 复现性

- AI 调用 `temperature=0.25`、`response_format=json_object`，同一输入仍可能有 3–8 分波动。
- 若需完全可复现：只用测评分（确定性），或把 AI 评分结果落库后人工复核。
- 建议面试官：**看维度与理由，不要只看总分**；对低分维度做二次追问。
